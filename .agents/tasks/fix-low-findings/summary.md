# Low findings L1 to L15 and the two minor issues

Nothing is committed. Info findings I1 to I11 and the C/H/M fixes were not touched. docs/NOTES.md was not edited.

## One line per item

- **L1 (poison outbox row): code + doc, no quarantine.** Quarantine or skip would let later events of the same order overtake the stuck one, so it stays "stop at the first failure". Added the counter `shopflow.outbox.publish_failures` (`OutboxRelay.FAILURES`, needs a `MeterRegistry` in the constructor) so an alert can fire, and documented in the class comment that a stuck row is fixed by hand. Test: `OutboxRelayRunLimitTest.aRejectedRowStopsTheRunAndIsCounted`.
- **L2 (dead letter without coordinates): code.** `DeadLetters` falls back to the record's own topic, partition and offset when the recoverer headers are missing. Test: new `DeadLetterCoordinatesTest` (fallback and header-wins).
- **L3 (send and mark are separate): code.** A DB error on the "mark published" update is caught, logged at ERROR with the event id, and ends the run. The row is re-sent next run (at least once, unchanged). Test: `OutboxRelayRunLimitTest.aFailureToMarkARowPublished...` (a check constraint makes the update fail; old code threw).
- **L4 (isOwner true for missing order): accepted, no change.** docs/user-stories.md asks for 404 vs 403. Reasoning added to the `OrderAccess.isOwner` javadoc, with the one-line change to make if ids become sensitive.
- **L5 (webhook secret length): code.** `PaymentWebhookProperties` refuses a non-empty secret shorter than 16 characters at startup. Empty stays allowed (webhook answers 503). Existing dev and test secrets are 23 to 25 characters, so no test needed changing. Test: new `PaymentWebhookPropertiesTest`.
- **L6 (CORS dev defaults): accepted, no change.** The yaml and `ShopFlowProperties` already say deployments must set `SHOPFLOW_CORS_ALLOWED_ORIGINS`. Moving the defaults to the dev profile would change what the CORS story test and a plain local start see, for a setting that only widens access to localhost origins.
- **L7 (CI comment): doc.** `ci.yml` header now says Error Prone and NullAway are configured in order-platform only.
- **L8 (skeleton modules): doc, modules kept.** Removing modules is the owner's call. Added `shopflow-starter/README.md` (placeholder, no purpose documented, how to remove it). inventory-service already had a README from M7. Cost is about 5 s of the build.
- **L9 (CI duration limits): config + comment.** Based on the recorded local `./mvnw verify` runs: 3:19 (review baseline), 2:26 (after C/H fixes), 2:42 (after M fixes), 2:41 (this run). The warn limit moved from 480 s to 360 s (about twice the slowest local run); the fail limit stays 600 s because it is the stated 10 minute target, not a measurement. The `ci.yml` comment says no hosted-runner timing has been measured, and that WARN_AFTER should be adjusted once run summaries exist. I did not measure a hosted runner.
- **L10 (load-test script deletes results): code.** `compare-virtual-threads.ps1` writes to `load-tests/results/runs/<timestamp>/` and no longer deletes anything; `.gitignore` ignores `load-tests/results/runs/` (logs and `.err` files land there). The committed `results/vt-*.json` cited by docs/NOTES.md are never touched. Checked only that the script parses; it was not run (it needs a 4 minute k6 run per mode).
- **L11 (silent skips): CI check.** New `.github/scripts/check-skipped-tests.sh`, run as a step after the build: sums `skipped=` in the Surefire XML reports and fails if it exceeds the number of `@Disabled` annotations in the test sources (currently 0). Also fails when no reports exist. Verified locally with Git Bash: 0 skipped gives exit 0; a report edited to `skipped="2"` gives exit 1 with the error line. Not run on a hosted runner.
- **L12 (oversized event payload): accepted, documented.** Throwing and rolling back is the right behaviour for an outbox written in the business transaction (saved together or not at all). Javadoc on `OutboxEvents.MAX_PAYLOAD_LENGTH` says so. No schema change.
- **L13 (cancel reason): accepted, comment.** After C2 only PENDING_PAYMENT can be cancelled through the status change, so the single reason "cancelled on request" is accurate. Comment at the call site; the cleanup job already uses "unpaid".
- **L14 (schema gaps): code + migration.** New `V11__orders_status_check.sql` adds `ck_orders_status` (CASE form, because H2 2.4.240 fails to evaluate `in (...)` or `a or b` checks after the migrating connection closes; found by running the H2 repository tests). `Order.reservationId` now declares `length = 64`. Test: `OrderRepositoryQueries.theDatabaseRefusesAStatusThatIsNotInTheEnum`, which runs on H2 and PostgreSQL; I confirmed it fails with V11 removed (`clean test`) and passes with it.
- **L15 (warnings): code.** `WebhookSignature` uses `split(",", -1)` (no StringSplitter warning; behaviour the same, empty parts are skipped by the existing length check). Removed the empty `<url/>`, `<licenses>`, `<developers>`, `<scm>` placeholders from the three module poms. `DeadLetters` ReferenceEquality left as is (intentional cycle guard). Test-code split warnings and the Mockito agent warning were not touched (not asked for).
- **(a) evict error after commit: code.** `CacheConfig.EvictUnreadableEntryHandler.handleCacheEvictError` logs at ERROR and does not rethrow, so a saved change is no longer reported as an error. A stale entry lasts until the TTL (5 min Caffeine, 10 min Redis). Put and clear errors still rethrow. Test: new `CacheEvictErrorHandlerTest`.
- **(b) skipped count in cleanup: code.** `UnpaidOrderCleanup` now counts an order as cancelled as soon as `cancelIfStillUnpaid` returns a reservation. A failed release logs "cancelled but its stock release failed" and the run goes on (InventoryUnavailableException still stops the run). `cancelOne` was inlined. Test: `UnpaidOrderCleanupOrderingTest.anOrderWhoseReleaseFailsWithAnOtherErrorIsStillCountedAsCancelled` (reads the summary log line: "2 cancelled, 0 skipped"; old code logged 1 and 1). Not run against old code, by reading only.
